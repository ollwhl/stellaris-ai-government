# 工具执行、中文报告与角色称呼

## 覆盖与边界

123 条随库 schema 均有明确的读写分类与领域映射，mock 逐工具处理器已补齐。领域包括科研、生产建设、舰队军事、探索扩张、政务议程、传统法令、领袖、物种权利、市场、遗珍、事件通知、游戏时间、存档新局。

这表示这些工具已进入行政执行框架与模拟状态机，不表示123条操作已在真实游戏验收。模拟候选、价格、成本和完成天数均为 mock 数据；并非游戏数值还原。未知的新工具仍不自动授予写入能力。

既有 research/construction/defense 项目保留专用行政路径。其他操作使用 generic 项目：scope.domain 指定领域，scope.allowedTools 指定工具，scope.maxActions 限制1至12次写入。同一项目可多轮查询候选，所有写入经 EXEC 的 schema、权限、对象、版本和预算检查。模型只提交公开依据，不保存隐藏思维链。

通用任务的步骤、实际输入/输出、查询结果和回读证据持久化。MCP accepted 与业务完成分开；响应丢失后先观察，不能盲重试。mock 根据已持久化操作记录和状态推进观察；真实模式使用内置回读规则或模型基于实际查询结构提出的 observe 条件。没有实际成本或可核验条件时暂停，并明确显示原因。

真实模式 observe 的格式是 `{tool,args,path,mode,value}`。tool 必须是已登记只读工具，path 是返回对象的点分路径，mode 支持 equals/includes/absent/gte/lte。写入前先读取条件，写入后再验证；条件在提交前已经成立时不重复下令。该框架仍需用户安排后做真实游戏效果验收。

市场每月交易为有限期限授权：scope.months 为1至12，默认1。mock 先保留整个期限预算，再按月份交易；到期显示等待后续授权，不会无限扣款。真实模式不能从候选核验成本时不会提交。

## 网页操作

权限面板新增各扩展领域开关。选择全局接管会开启日常经营领域，仍保留预算、对象接管、暂停角色和停止控制。游戏时间、存档/新局和手动调试写入单独授权。旧配置不会在升级时悄悄扩大权限，可在面板点击“启用全局接管并恢复执行”明确启用。

全局报告展示中文字段、资源库存与月净收入、各领域科研、星球建设、舰队和缺失信息。当前及历史决策报告使用同一展示组件，原始 JSON 留在调试折叠项。未知字段保留原键，不编造译名或数据。资源预算也有中文数值输入。

“模型与知识”中新增“政体与部门名称”：五个稳定运行角色都可自定义1至30字符，支持共和制、君主制、企业制、蜂巢思维和机械智能预设。名称保存在 SQLite 配置内，用于界面和后续模型输入；修改名称不改变职责和授权，也不改写历史发言正文。

## 本轮验证范围

只进行严格 TypeScript、生产构建和静态 schema/处理器覆盖检查，按用户要求没有在 VPS 运行浏览器或业务自动测试。试用仍为 mock 游戏 + 服务端真实模型 + Wiki 知识。屏幕会话与公网8001部署方式保持不变，8000不改。

## AI 总开关

页面顶部、指挥中心侧栏和权限面板提供 AI 总开关。关闭后清空政府待运行队列，停止定时战略重评和行政新决策；模型层取消正在进行与排队中的本机请求，并拒绝新的调用。通过开关代次和权限修订防止快速关开后使用旧结果。提供商已经收到的请求可能仍产生已发生的用量，取消本机请求不代表提供商撤销计费。

开关持久化为 Permissions.aiEnabled，关闭后重启仍保持关闭。关闭期间可查看状态、历史和知识，或保存新目标；保存目标不会触发模型调用。开启后按最新目标重新规划，原有接管模式、停止新提交、预算、角色暂停和对象权限仍保留，不扩大权限。

网页与只读状态采集继续工作，已提交订单和未知结果继续观察；已提交的游戏订单不会被伪装为撤销。原“停止新提交”开关继续保留，单独控制自动游戏写入，与 AI 总开关区分。人工明确授权的调试操作不属于自动接管。

## 各 AI 的唤醒频率

“模型与知识 → AI 唤醒频率”为五个稳定运行角色分别设置计时模式和间隔，名称沿用政体配置。

- 现实时间：按实际经过的时间计时，可选秒／分钟／小时。
- 游戏时间：按当前对局日期计时，可选游戏天／月／年。1月=30天，1年=360天；日期不推进便不累计，未知日期不触发游戏周期。

默认四个政府角色每30现实分钟一轮，行政角色每2现实秒检查新决策机会。后台变化与执行反馈按相关角色周期合并；周期到期只邀请到期角色，不再写死每30分钟全体开会。玩家主动下令、手动重评、权限变更和对局切换仍立即处理。最高决策角色的一轮包含方向与裁决两次调用，行政一轮可以处理多个项目，频率不是单次 API 请求的节流数。

唤醒计时保存在 SQLite；保存配置时相关角色从当前时刻／当前游戏日期重新计时，保存本身不调用模型。总开关关闭、角色暂停期间不唤醒，恢复后重新计时；游戏时间倒退或切换对局重置时间基线。错过多轮不会补跑多次。实际触发精度受后台轮询周期约束，默认约2秒。

行政的新模型决策受周期限制，已提交订单和未知结果的只读观察仍持续。游戏时间模式下的新战略有效期也按游戏日期判断，不再被旧的30分钟现实截止规则截断。改变策略计时方式前已有的历史战略仍保留原有效期，新一轮战略使用新配置。

## 行政事件自治与上报

事件弹窗不再要求玩家先建立项目或逐个批准。情报层持续采集 active events、notifications、alerts；行政有独立巡检循环，普通建设/科研的慢模型不会阻塞事件发现。常规弹窗根据当前玩家目标、战略、资源底线及授权预算自行选择真实可见选项。重要、不可逆或无法判断的取舍自动转交最高决策角色；该角色有独立裁决接口，返回具体选项或观察依据后，由 EXEC 继续执行。重大事件处理不等待普通唤醒周期。

战争通知关键词以及明确的战争状态从无到有／新战争编号会形成重要上报。不能把缺失战争数据当作和平，也不把首次观察到战争当作刚刚宣战；战争进度变动不反复报新战争。相同窗口和内容去重，已知 war_id 相同的通知与弹窗关联，不重复唤醒。最高角色实际裁决可立即组织总统／军事的应对规划，规划读取上报证据，但不改变玩家目标或扩大授权。

事件不是任意项目的权限旁路：仅对绑定事件的 resolve_event/open_notification/open_alert 授予有限执行资格；提交前重新读取当前窗口/选项与消息序号、核对权限修订、方针签名、对局时间线和成本。资源支出经原预算账本预留，遵守共同资源底线。最高角色同样不能扩大玩家预算、领域或人工接管范围。仅建议、停止新提交、暂停角色或关闭总开关继续有效。总开关关闭时只记录与观察，不调用行政或最高角色模型。

没有可核验成本或合法选项时，行政上报；最高角色优先选已有的合规替代方案。若仍缺情报，自动保持观察、在事实变化或退避周期后重评，不生成“等玩家批准”的流程，不猜测成本或伪造成功。模型失败采用退避重试，行政多次失败转上报。未知写入结果保留预算并先观察，不重复点击。窗口消失但提交结果未知时，不声称已选项成功。

“状态与任务 → 事件处置”展示发现、行政判断、上报、实际裁决、所选项、提交与回读，实际输入/输出可展开并按 trace 导出；不记录隐藏思维链。mock 提供常规弹窗、重大取舍和被宣战三个手动模拟入口，不连接真实游戏。实际游戏的提示文本、成本结构、版本差异仍需用户安排后验收。

## 战场态势与持续舰队任务（2026-11-11）

入口为「战场态势」。程序独立采集己方舰队、已知地图与星系详情，缓存拓扑并限制每轮扫描数量；扫描频率不等于模型唤醒频率。记录可见敌舰、最后观察时间、失联/过期、局部力量对比、交战状态及损伤缺失项。未知关系不认作敌对，失联不认作被击败。边境入侵、开始交战、指令中断和重大威胁可绕过常规军事时钟，首都威胁与重大损失上报最高决策角色；总开关关闭只记录和回读。

军事角色可发布 `fleet` 项目，行政执行器按明确候选分阶段提交，支持驻守、集结、指定敌舰攻击/追击、己方护航、撤退、整补和运输登陆。界面也可建立玩家指定任务，优先于自动规划；每支舰队只允许一个任务实际控制。任务和命令持久化，记录实际输入、公开模型输出、命令与后置观察。阶段决策按语义事实去重，不以轮询时间反复请求模型。同一持续任务明确失败至少间隔30秒，累计3次后停止提交并上报，需军事修订处理。

所有写入仍经 EXEC，核验总开关、授权版本、项目/任务修订、对局、人工对象接管、路径与预算。未知写结果先观察，保留预留；重启不盲目重发。战略局部修订仅沿 `project_rebases` 承接范围和预算均未变的任务。防守/护航为持续任务；抵达、接受命令、持续订单、击败目标和夺取星球分别判断，不能用工具返回成功替代业务完成。

「权限」新增主动进攻/登陆、紧急跃迁两项独立开关，默认关闭，全局接管不会自动开启；任务也必须允许紧急跃迁。暂停/取消任务及人工接管停止后续提交，不能宣称游戏内旧命令撤销；新任务接替失效旧任务时，若仍有指令须先明确取消并回读。未知结果期间不接替。

Mock 追加已知航道、边境防卫舰队、运输队和可见外舰，支持入侵、敌方增援、目标失联、封锁/恢复路径、损伤和明确击败场景；通过界面推进游戏时间观察移动、跟随/交战、撤退、维修及登陆模拟进度。这些是明确标注的模拟事实，不代表真实桥接能力已经验收。真实桥接若不提供敌对身份、损伤、命令队列或费用等字段，显示未知并保留执行约束，不修改桥接或推测补齐。
