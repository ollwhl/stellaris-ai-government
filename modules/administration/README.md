# 行政执行与控制

`createAdministration(context,getIntel)` 是唯一游戏调用入口。`integrations/game_mcp/client.ts` 管理真实 stdio 客户端，实际工具目录动态读取；`contracts/game-tools.json` 是从指定依赖版本抽取的完整离线目录。mock 的14条受支持路径使用同一 schema，其他工具仍可浏览但返回未实现，绝不伪造成功。

默认仅建议。程序检查授权修订、业务域、项目修订、战略修订/有效期、对象范围、人工接管及部门暂停。`controlledObjects` 使用 `planet:0` / `fleet:0` / `research:physics`。暂停、继续、调速分别授权。未知效果工具只允许明确调试授权；情报入口不得调用。

写入串行化；提交前再次检查授权。预算事务预留按库存扣除未决预留与战略底线，限制项目承诺额和玩家预算。接受与完成分离。建设/舰队入队后继续观察，科研选项回读后确认已接受，待研究实际完成后才标记项目完成；结果未知先观察，禁止盲目重试。预算与任务、调用均持久化。对局时间线变化后旧未决任务阻塞等待核对。

`advanceMock(days)` 明确推进模拟日期与队列（不受暂停开关约束，是开发控制）。`mockControl({resources:{minerals:100},unknownNext:true})` 可模拟缺口及执行后丢失响应；`failNext:true` 模拟未执行的确定性拒绝；`timelineId` 模拟读档/切局，`reset:true` 重置模拟对局。

当前自主业务范围是科研选择、建筑建设、舰队增援。其余工具可由玩家调试并留原始记录，后续按实际任务登记效果与观察规则，不复验整个桥接。实际资源/队列的差异保留在原始调用与后置观察，不使用屏幕识别。

一次性项目授权：`permissions.oneTimeProjectIds` 显式列出批准的项目。advice 模式仍允许该具体项目执行，无需开启整个领域的权限；停止、对象范围、人工接管、预算及版本检查不放宽。授权内部绑定当时项目修订与时间线，项目修订或换局后失效，完成/取消自动移除。已完成项目不可再次批准。项目等待期间授权持续有效，不能把“选择研究成功”当成整项研究已经完成。

局部战略 rebase：仅当 `project_rebases` 存在从旧任务修订到当前项目修订的完整明确链时，已提交/已完成任务才承接到新修订，保留原调用、观察条件及资源记录；不会再次下单。真正修改计划形成的修订间隙不会被推测为 rebase。任务承接产生 `task.rebased` 事件，并按当前修订反馈已有完成结果。
